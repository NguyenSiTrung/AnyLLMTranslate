# Initial Concept

AnyLLMTranslate — an open-source Chrome extension that replicates and extends the core value proposition of Immersive Translate: bilingual side-by-side web page translation and video subtitle translation, powered by any OpenAI-compatible LLM endpoint (fully BYOK).

---

# Product Guide

## Vision

AnyLLMTranslate is an open-source, privacy-first Chrome extension for immersive bilingual translation. It enables users to read web pages in their native language alongside the original text, and translates video subtitles on learning platforms — all powered by any LLM the user brings.

## Target Users

- **Language learners** who want bilingual reading to improve comprehension
- **International professionals** reading foreign-language articles, documentation, and reports
- **Online course students** on platforms like Udemy, Coursera, YouTube, and LinkedIn Learning who need subtitle translation
- **Privacy-conscious users** who prefer self-hosted or local LLM backends (Ollama, LM Studio, vLLM)
- **Developers/power users** who want full control over their translation pipeline

## Core Value Propositions

1. **Bilingual Side-by-Side Display** — Translated text appears below/beside original paragraphs with minimal layout disruption, supporting 15+ visual themes
2. **Video Subtitle Translation** — Real-time bilingual subtitles on Udemy, Coursera, YouTube, LinkedIn Learning, HBO Max, Youku, and other platforms (plus a generic fallback) via XHR/fetch interception and DOM cue scraping
3. **Universal LLM Backend (BYOK)** — Connect to any OpenAI-compatible API (OpenAI, DeepSeek, Groq, Ollama, LM Studio, vLLM, **Google AI Studio / Gemini**, Claude via proxy, or other compatible gateways) using a searchable provider catalog and on-demand model picker; optional **thinkingMode** (`auto`/`on`/`off`) with Gemini **thinkingEffort** and **DeepSeek (Official / OpenCode Zen)** thinking support; Google AI Studio free-tier **multi-model pool** (`preferred_failover` / `round_robin`)
4. **Premium Display UX** — Multiple translation themes (underline, highlight, bubble, mask, fade-in), dark mode, loading/error states
5. **Smart DOM Translation** — Viewport-based lazy translation, SPA support via MutationObserver, intelligent paragraph detection

## Key Features

### Page Translation
- DOM walker with intelligent paragraph detection
- Viewport-based lazy translation (IntersectionObserver)
- SPA / dynamic content support (MutationObserver), including **body-swap re-init** (full-document SPA navigations that replace `<body>`)
- **Selector-match cache** (`matchesCached`) for skip-list checks during extraction
- **In/out-of-article batch split** — pieces tagged `inArticleContext` ship in separate LLM batches so sidebar chrome does not dilute article context
- **Page-scope presets** (Classic / Balanced / Main content / Full page) — single control mapping smart excludes, body whitelist, and aside caps; **Balanced is the product default** (streaming + aside caps ON). Classic restores pre-v3 defaults as escape hatch (`lib/pageScopePreset.ts`)
- **Page Walk Tuning** (Options → Advanced): body-tag whitelist (direct children of `<body>`) + aside region text caps (aside caps default **ON** under Balanced)
- **Viewport-aware progress** — status distinguishes reading-strip idle vs whole-page complete (`lib/webTranslateStatus.ts`); popup copy like “Reading area ready · N more as you scroll”; in-page **mini progress** (`content/miniProgress.ts`)
- **Sticky systemic-pause banner** — on pool death / systemic pause: in-page bar with Retry / Dismiss / Settings; Dismiss hides UI but keeps pause so scroll does not storm a dead pool
- **Throughput v3** — parallel sub-batches (`runWithConcurrency` cap 3), look-ahead prefetch (one hop, `isLookahead`), reading-strip priority sort; session settings cache + parallel cache lookups; opt-in adaptive batching
- **Quality v3** — document term memory, JSON parse salvage/repair, expanded langDetect, optional model-scoped cache, category prompt snippets, opt-in quality self-check; stream path loads settings/glossary + pageContext/termMemory for parity; resume identity via parentPath+text
- Translation cache via IndexedDB (success + negative/failure cache with TTL; manual retry bypasses failure cache)
- **Streaming translation default ON** (`enableStreamingTranslation`; non-stream fallback retained)
- **Compact inline for short text** toggle (default off) for denser bilingual display on short pieces
- Restore/undo translation

### Video Subtitle Translation
- XHR/Fetch interception via MAIN world script injection
- Platform handlers: YouTube, Udemy, Coursera, LinkedIn Learning, HBO Max, Youku (+ Generic last-resort fallback; Disney+/WeTV/Netflix handler stubs exist)
- **DOM cue scraping** for platforms that render captions into the DOM (HBO Max, Youku) — no VTT URL or native TextTrack; MutationObserver on stable ancestor samples `video.currentTime` to derive cue timing; per-platform selector + activation attribute declared via the `DomCueSource` contract
- **Auto font size mode** for subtitles — scales font size proportionally to video height (clamped to min/max), recalculated on video resize via ResizeObserver
- WebVTT parser and bilingual builder
- Custom subtitle overlay (fallback renderer)
- Drag-and-drop subtitle repositioning with session persistence
- Proactive subtitle track discovery (HTML5 TextTrack + platform handlers)
- **Per-site subtitle toggles** — Settings card lists supported subtitle platforms with enable/disable switches; content-script coordinator skips the pipeline when a site is disabled (`disabledSubtitleSites`)
- **Profile-driven subtitle prompt** — each subtitle site's hostname resolves to one of three profiles (`educational` / `media` / `cinematic`), each presetting four translation knobs (**Register**, **Faithfulness**, **Brevity**, **Profanity**) that drive a dedicated subtitle system prompt (separate from the generic web-page prompt). Resolution happens in the content script (no `tabs` permission).
- **Subtitle context & continuity** — bidirectional chunk look-ahead (forward cues seeded into chunk 0), a per-session **rolling proper-noun glossary** that accumulates names as chunks translate, and VTT `<v Speaker>` voice-tag parsing carried into the prompt.
- **Per-film proper-noun extraction** — a dedicated name-extraction pre-scan prompt runs once per film, seeds the rolling glossary with canonical names before chunk 0, and is cached in `chrome.storage.local` keyed by content hash (`lib/subtitleFilmGlossary.ts`, `services/filmGlossaryStore.ts`).
- **Named subtitle glossary lists** — user-owned personal dictionaries (e.g. show/course packs) separate from global Custom terms. Options → Custom terms manages lists (create/rename/delete, entry CRUD, caps 50 lists / 200 entries); popup selects the active list per subtitle site with **last-used-on-this-site** memory (`subtitleListBySite`); authority order **named (locked) > global > film seed > rolling** so auto merges cannot overwrite user terms; suggest → edit → push from film/rolling names (`lib/namedGlossaryLists.ts`, `lib/namedGlossarySuggestions.ts`, `NamedGlossaryListPanel` / `NamedGlossarySuggestionsModal`); subtitle system prompt injects a personal-dictionary block; cache key folds list id + entry snapshot; **forward chunks re-resolve** the hostname-selected list (not only session start)
- **Editable translation knob overrides** — the four knobs are user-editable at two layers: a persisted **global override** (Options → Subtitles → Translation Style) and a session-scoped **per-tab override** (popup Subtitle style expander). A pure `resolveEffectiveKnobs(profile, global, perTab)` helper merges in precedence order (per-tab > global > preset); with both empty, behavior is identical to the profile preset.
- **Reading-speed timing adaptation** — display-duration limiter that extends too-short cues to a minimum reading window (words / WPM) and compresses too-long cues, preventing both flash subtitles and lingering stale text. Pure helper in `lib/subtitleTiming.ts`, wired into the coordinator's cue-update loop.
- **Line-wrapping in subtitle overlay** — wraps long translated lines into multi-line divs with a dynamic char-per-line budget derived from overlay width and font size. Prevents overflow truncation on narrow players and CJK text without manual line breaks.
- **Context-aware subtitle cache & chunk retry** — subtitle cache key folds in resolved profile/knobs + glossary snapshot (`lib/subtitleCacheKey.ts`, `subtitle:` namespace prefix isolates from web-path cache) so different knob settings or glossary state produce separate cache entries. Failed chunks retry with exponential backoff (`lib/subtitleRetry.ts`); `SUBTITLE_CHUNK_FAILED` surfaces as an idempotent toast for user-visible error feedback.
- **YouTube ASR sentence re-alignment** — pre-translate re-chunk of auto-generated captions (`kind=asr`) into sentence-like cues via local Immersive-style rules (`lib/youtubeAsrResegment.ts`) with optional AI/BYOK resegment (`RESEGMENT_YOUTUBE_ASR`, index-range partition, fail-open to local). Successful AI runs are cached in IndexedDB (`services/youtubeAsrRealignStore.ts`, pure keys/LRU in `lib/youtubeAsrRealignCache.ts`) keyed by video/lang/content hash; runtime mini-progress shows re-align stage, batch `i/n`, and “Using saved re-align” on hit. Options → Subtitles → Caption quality (toggles + summary) and **Saved caption re-aligns** manager (list/delete/clear/force re-run). YouTube first-load CC-on intercept recovery + unified ASR path; native CC hidden under the bilingual overlay. Human tracks and non-YouTube platforms unchanged.
- **Player Subtitle Chrome (in-player mini studio)** — on-player icon + mini studio panel on any subtitle-capable video page (`content/playerChrome/`): **hybrid mount** (native control-bar injection via per-site adapters for YouTube/Udemy/Coursera, rect-tracked **floating fallback** anchored to the player shell everywhere else — native failure never removes the feature), **soft-mirror visibility** state machine (icon follows player control visibility via adapter signal or activity heuristic; an open panel stays sticky until dismissed), fullscreen reparenting/geometry parity, and a richer control set wired to **existing** prefs (enable, display mode, font size, position, background opacity, 4 style knobs, named glossary list, status line, footer link to the full Subtitle Studio) — shadow-DOM isolated, tight hit targets, no second settings schema. Design/plan: `docs/superpowers/specs|plans/2026-07-31-player-subtitle-chrome-*`.

### PDF Translation
- Built-in PDF.js viewer (`entrypoints/pdf-viewer/`) — **reader-first shell** with optional original|result compare (Approach B, 2026-07-20)
- **PDF Translate is Docker-bridge only** — layout-preserving translation via a local **Scientific PDF bridge** wrapping [pdf2zh / PDFMathTranslate](https://github.com/PDFMathTranslate/PDFMathTranslate) (`services/scientific-pdf-bridge/`). There is **no in-browser “Fast” LLM translate path** in the viewer: when the bridge is offline or not configured, translate controls show **unavailable** with setup CTA (wizard / docs). Same **provider pool** credentials injected per job (no second API key UI). Default server `http://127.0.0.1:17890`; Options → Advanced → **Scientific PDF** card + setup wizard; helper scripts `scripts/scientific-pdf-docker.sh` (+ up/down). Outputs: **mono** + **dual** (bilingual layout) download; open dual/mono in the viewer. Job progress modal with logs and format choice (post-ship UX redesign). See `docs/scientific-pdf-setup.md` and `docs/scientific-pdf-bridge-api.md`.
- **Shell modes (`PdfShellMode`)** — session-only (not persisted across documents):
  - **`reader`** (default) — full-width single PDF column; idle hero is the source document; after “Open translated,” reader focuses the result with Back to original / Compare actions
  - **`compare`** — two scroll-synced panes **Original | Translated** (mono or dual result), only when a result blob is held; header mode toggle disabled until a result exists
  - Pure session helpers in `entrypoints/pdf-viewer/lib/pdfShellMode.ts` (`initialSessionState`, `applyOpenTranslated` / `applyOpenCompare` / `applyShellMode`, pane labels); `PdfDocumentPane` renders each role; bridge health is **chrome** (pill + offline setup overlay), not a permanent half-pane content column
  - **Supersedes** legacy `PdfViewMode` (`split` / `translation-only`) and permanent `BridgeStatusPanel` half-grid — design: `docs/superpowers/specs/2026-07-20-pdf-viewer-reader-compare-design.md`
- **PDF auto-detection** — content script detects standalone PDF tabs via `document.contentType === 'application/pdf'`, which catches extensionless URLs (e.g. `https://arxiv.org/pdf/2606.20543`) that URL-suffix heuristics miss — no `webNavigation`/`webRequest` permissions needed
- **Auto-open translator** — optional setting (`Options → Advanced → PDF Translator`, `pdfSettings.autoOpen`) with three modes: `off` (default, manual popup/context-menu only), `prompt` (in-page banner), `auto` (opens the viewer immediately on PDF tab load). Safeguards: infinite-loop guard (suppressed on `chrome-extension://` origins), provider-readiness gate, per-tab dedupe in `chrome.storage.session` (survives service-worker eviction), per-site opt-out (`neverAutoOpenSites`), and new-tab vs same-tab open modes
- **Popup detection wiring** — popup queries the content script for `getPageContentType`, lighting up the "Open current PDF" button even for extensionless PDF URLs
- **Composition pipeline (BabelDOC-inspired, retained for typesetting/export helpers)** — run-level extraction, multi-signal formula detection, `{vN}` placeholders, table regions, multi-column order, selective masking, shared typesetting ladder + dual export assembly from mono — used by download/typesetting paths; **viewer translation jobs go through the Scientific bridge**, not the old paragraph streaming pipeline
- **BabelDOC-parity features** — dual export modes (mono / side-by-side / alternating), document term extraction into term memory, scanned-page detect + OCR workaround banners, PdfSettings toggles (`autoExtractTerms`, `detectScanned`, `autoOcrWorkaround`)
- **Power-user PDF card** (Options → Advanced → PDF Translator) — composition toggles (e.g. **Translate table text**, **Strict math skip**); auto-open / never-auto-open hosts remain
- Dual/mono PDF export via `pdf-lib` (Helvetica fallback; custom fontkit embedding removed from the default dependency set)

### Translation Engine
- Universal translation provider supporting OpenAI-compatible and Langflow endpoints
- **Provider catalog** includes Google AI Studio (Gemini) OpenAI-compat base URL alongside OpenRouter, NVIDIA NIM, Groq, Together, Fireworks, Mistral, Ollama, LM Studio, custom
- **thinkingMode** (`auto` / `on` / `off`) per provider — `auto` omits thinking fields (server default); NIM/Nemotron/Qwen3 via `chat_template_kwargs.enable_thinking`; Gemini via top-level `reasoning_effort` + optional **thinkingEffort** (`minimal`/`low`/`medium`/`high` when On); **DeepSeek Official** via DeepSeek thinking-mode/effort params and **OpenCode Zen DeepSeek models** via the DeepSeek thinking API; StepFun reasoning-only responses (empty `content`) are handled gracefully. Self-heal when endpoints reject kwargs (`lib/thinkingMode.ts`)
- Request batching & deduplication
- Custom glossary/term protection
- Configurable system prompts
- LLM response sanitization — strips `<think>` blocks and extracts JSON from markdown code fences or raw brace extraction
- **Provider capability self-healing** — when an endpoint rejects `response_format` (e.g. NVIDIA NIM / vLLM on models without a JSON schema), the request is auto-retried without it and the rejection is remembered on the service instance so every subsequent request sends the clean body directly; resets on provider/model switch
- **User-configurable RPM rate limiting** — sliding-window limiter at the single network chokepoint (`OpenAICompatibleService.fetchWithRetry`) caps requests-per-minute against providers with rate limits; `maxRpm` (0 = unlimited) on `ExtensionSettings` + `ProviderConfig` / per-key pool slots
- **Safe default key throttle** — new keys and fresh installs default to `maxRpm=20`, `concurrencyLimit=1`, `interval=500ms` (not unlimited 0); existing all-zero keys upgraded once via `safeKeyThrottleMigrated`; users can still set 0 for unlimited. Concurrency/interval participate in the pool signature so rebuild detects throttle edits.
- **Multi-provider pool with round-robin & circuit-breaker failover** — multiple active providers + multiple API keys per provider; requests distribute round-robin across all enabled, healthy `(provider, key)` slots (per-key RPM, summed throughput ≈ Σ keys' maxRpm). Circuit-breaker failover on 429/5xx/network → escalating cooldown (60s→120s→300s), on 401/403 → long-open (1h) + `credentialInvalid` flag. Pool exhaustion exposes earliest `openUntil` for UI countdowns. A `ProviderPoolCoordinator` sits at the single `initService()` seam so all 7 translation paths are covered in one place. Options → Providers tab is an **ops dashboard** (rotation list, key status chips, rate-limit presets, edit drawer, guided add from catalog). Legacy single-provider users migrate automatically into `providers[0]`.
- **Google AI Studio multi-model pool** — free-tier Gemini limits are **per model** (and per project, not per key). A single Google AI Studio pool provider may list multiple models (`PoolProvider.models[]`, `models[0]` = preferred / `model`). Strategies: **`preferred_failover`** (default; quality-first — preferred model across keys, then ordered alternatives) and **`round_robin`** (throughput-first — equal healthy `(key × model)` slots). Composite slot identity `keyId::model` so one model’s 429/cooldown does not cool sibling models on the same key. Non-Google providers stay single-model. Pure helpers: `lib/googleMultiModel.ts`; expansion in `lib/poolResolver.ts`; dispatch in `services/providerPool.ts`; UI “Free-tier multi-model” in Provider edit drawer. Design/plan: `docs/superpowers/specs|plans/2026-07-23-google-ai-studio-multi-model-pool-*`.

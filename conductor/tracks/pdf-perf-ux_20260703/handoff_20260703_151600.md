## Key Implementation Decisions

### 1. Eviction Architecture (Phase 1 Task 1)
- `usePdfDocument` accepts optional `{ visiblePages?, evictionWindow? }`
- Eviction effect reads `visiblePages` from `App.tsx` (which computes it via `useVisiblePages` using `numPagesRef` from previous render to resolve chicken-and-egg)
- **Critical insight:** Eviction is *proxy-only*. Extracted text + translations live in `pdfTranslation.ts` `memoryCache` + IndexedDB — independent of pdf.js proxies. Re-entering an evicted page serves from cache, no LLM call.
- `PDFPageProxy.cleanup()` is **synchronous** (returns `boolean`), not a Promise. Wrap in try/catch.

### 2. Keep-Alive Alarm Coordination (Phase 1 Task 2)
- `clearKeepaliveAlarm()` must check **both** `activeSessions.size === 0 && pdfSessions.size === 0`
- Subtitle-only check would incorrectly clear alarm while PDF viewers are open.
- Pure helpers in `pdfSession.ts` (`registerPdfSession`, `unregisterPdfSession`, `shouldArmKeepalive`) operate on injected `Set<number>` — background owns the live Set + chrome.alarms calls.

### 3. Streaming Translation Design (Phase 2 Task 1)
- **Pure parser + real-service integration test split:** SSE parsing (`parseSSEBuffer`, `extractDeltaContent`, `extractCompletedPieces`) lives in `lib/sseStreamParser.ts` (testable with plain strings). Service test uses REAL `OpenAICompatibleService` with mocked `fetch` returning `ReadableStream` — catches contract bugs at both layers.
- **Incremental JSON piece extraction:** `extractCompletedPieces(buffer, knownIds)` scans for completed `"id":"value"` pairs (closing quote + comma/brace present). Enables per-paragraph fill without waiting for full object.
- `translateStream?()` is **optional** on `TranslationService` — pool falls back to non-streaming `translate()` when member lacks it (emits all pieces at once via callback).
- **Error contract:** Transport/auth/rate-limit failures **re-throw** `ApiError` (carrying `statusCode`) so caller falls back to non-streaming. Content problems return `{success:false}`.

### 4. Per-Paragraph Status (Phase 2 Task 2)
- `PageTranslations` gains `paragraphStatus?: Map<id, ParagraphTranslationStatus>`
- Status transitions: all paragraphs → `'translating'` on page start, → `'success'` as results arrive (or `'error'` on page failure)
- Cache-hit path marks all cached paragraphs `'success'`
- `result.current` staleness in `renderHook` tests: assert INSIDE `waitFor` callback, not after it resolves.

### 5. Port-Based Streaming (Phase 2 Task 3 — In Progress)
- `chrome.runtime.sendMessage` is request/response only — cannot push deltas.
- Introduced port protocol (`PDF_STREAM_PORT = 'TRANSLATE_PDF_STREAM'`) with message types: `PdfStreamRequest` → `PdfStreamPiece` (multiple) → `PdfStreamDone` | `PdfStreamError`
- Background `onConnect` listener calls `service.translateStream()`, pushes pieces via `port.postMessage`, posts terminal message on completion/error.
- Viewer-side `sendTranslationBatchStreamed()` opens port, collects pieces via callback, resolves with final results. Rejects on any error → caller falls back to non-streaming.
- `translateParagraphs(pdfUrl, onPiece?)` now accepts optional `onPiece` callback. Each prose batch tries streaming first, falls back to non-streaming on error. Correctness guaranteed by fallback.

## Learnings Extracted (Current Section)

### Patterns Discovered
- **Pure-helper-at-seams:** Decision logic extracted to pure functions (`pdfSession.ts`, `sseStreamParser.ts`) operating on injected data structures — fully testable without chrome API mocking. Background owns the live state + chrome.* calls.
- **Optional interface methods for new paradigms:** `translateStream?()` is optional on `TranslationService`. Pool delegates to first member supporting it; falls back to non-streaming when absent.
- **Incremental JSON piece extraction:** Regex scan for completed `"id":"value"` pairs (closing quote + comma/brace) enables per-paragraph fill without full object parse.
- **Port-based streaming for push semantics:** `chrome.runtime.sendMessage` is request/response. Streaming requires `chrome.runtime.connect` port with custom message protocol.

### Gotchas Encountered
- **`PDFPageProxy.cleanup()` is synchronous** (returns `boolean`) — don't `.catch()` it.
- **Chicken-and-egg hook wiring:** `usePdfDocument` (needs visiblePages) and `useVisiblePages` (needs numPages). Resolution: compute `useVisiblePages` FIRST using `numPagesRef`, feed result into `usePdfDocument`.
- **`renderHook` `result.current` staleness:** Assert INSIDE `waitFor` callback, not after it resolves.
- **`setPages(prev => prev)` (returning same ref) inside an effect can race** with another effect's `setPages(newArray)` under React 19 concurrent rendering in tests.
- **Test fixture JSON escaping:** `'...\"wörld\"...'` produces `"` not `\"` — use `\\"` for literal escaped quote in JSON.
- **Keep-alive alarm shared across session types:** `clearKeepaliveAlarm` must check ALL session sets (subtitle + PDF), not just one.

### Context for Next Session
- Streaming port protocol lives in `types/messages.ts` (`PDF_STREAM_PORT`, `PdfStreamPortMessage` union).
- Background port listener: `initPdfStreamPortListener()` in `services/background.ts`.
- Viewer streaming entry point: `sendTranslationBatchStreamed()` in `entrypoints/pdf-viewer/lib/pdfTranslation.ts`.
- `translateParagraphs(pdfUrl, onPiece?)` signature change: optional third param for incremental callbacks.
- `PdfTranslationPane.tsx` now renders streaming tail spinner when `state === 'translating'` but `paragraphs.size > 0`.

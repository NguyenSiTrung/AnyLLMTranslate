### From youtube-asr-resegment_20260709 (direct predecessor)
- Pure libs under `lib/` with no Chrome APIs — preferred for TDD; a pure lib cannot
  network — AI calls must go through background/pool.
- Word-level only when JSON3 segs have explicit `tOffsetMs`; multi-seg without offsets =
  coarse join (not per-seg words).
- ASR detect = `kind=asr` URL OR `isAutoGenerated` track meta.
- Pipeline order: parse → resegment → translate → adaptCueTimings (display path).
- Prefer LLM returning index ranges (not free text/timestamps) so timing stays
  deterministic; normalize ranges to a full partition.
- Coordinator tests: `vi.resetModules()` before dynamic import; call `startCoordinator()`
  explicitly.

### Cache/progress spec invariants (docs/superpowers/specs/2026-07-27)
- Cache key `ai:{videoId}:{language}:{contentHash}`; contentHash over the raw ASR input
  units (text + timings), so caption body changes miss correctly.
- Language: track language code as used by the coordinator (`originalLanguage || 'en'`).
- Successful runs saved on device; changing models does not auto-invalidate (Force re-run
  is the manual escape hatch).

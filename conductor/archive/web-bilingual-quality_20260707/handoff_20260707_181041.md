## Key Implementation Decisions

### FR-1 (Rich Translate)
- **Pure lib `lib/richTranslate.ts`:** `encodeInlineHtml` uses a regex TAG scanner + stack to handle nested inline elements; `decodeInlineHtml` uses a recursive `<z id="N">` scanner that builds via `createElement` only. XSS guard rejects `<script>`, `on*` handlers, `javascript:` URLs.
- **Integration point:** `domWalker.flushPiece` encodes `anchorElement.innerHTML` when `enableRichTranslate` and the piece isn't split (single-piece anchors only). Long pieces degrade to plain text (safe).
- **System prompt rule:** Added explicit `<z id="N">` placeholder instruction (opening + closing tags must be preserved exactly).

### FR-2 (Batcher + Char-Budget)
- **Deleted dead code:** `services/batcher.ts` + its test had zero prod imports (confirmed via grep).
- **Pure helper:** `lib/textBatching.ts` — `splitPiecesIntoBatches` (count + char budgets) + `dedupPiecesByText` (Map by text, first wins).
- **Handler change:** `handleTranslate` now dedups, splits into sub-batches, loops `service.translate`, merges, re-hydrates dupes. `totalApiCalls` stat reflects sub-batch count.
- **Return shape:** `TranslationResultMessage.partial` only set when true (spread `...(anyPartial ? { partial: true } : {})`) to preserve strict `toEqual` tests.

### FR-3 (Source-Language Gate)
- **Pure lib `lib/langDetect.ts`:** Script-range for CJK/Hangul/Kana/Cyrillic/Arabic/Hebrew/Thai/Devanagari (≥0.9 confidence); Latin n-gram + unique-diacritic fast-paths (vi: ă/ơ/ư/đ + hook/horn marks; pt: ã/õ; de: ü/ö/ä/ß); stopword scoring for en/es/fr.
- **Content gate:** In `translatePieces`, when `enableSourceLanguageDetection && sourceLanguage==='auto'`, pieces with `detected.lang == targetLanguage && confidence ≥ 0.55` are skipped (spinner cleared, marked translated with source text).

### FR-4 (Negative Cache)
- **Namespace:** `negative:` + same SHA-256 key as success cache. `NegativeCacheEntry { key, error, cachedAt }`.
- **Handler change:** Split loop checks `getCachedFailure` → push to `failedResults`; batch failure writes `cacheFailure` for each piece in batch.
- **Return shape:** `TranslationResultMessage.failed?: { id, error }[]`.
- **Content handling:** `response.failed` → per-piece error state with retry closure.
- **Eviction guard:** `evictCache` skips negative entries from LRU size/sort (they lack `sizeBytes`/`lastAccessedAt`).

### FR-5 (Per-Key Concurrency + Throttle)
- **PoolSlot extension:** `concurrencyLimit`, `interval` threaded through `buildSlot`/`resolveSlots`.
- **Coordinator state:** `inFlight` (count), `keyQueues` (FIFO resolve callbacks), `lastDispatchAt` (ms).
- **Dispatch path:** `acquireKeySlot` (blocks on limit, FIFO wake on release) + `applyKeyThrottle` (sleeps `interval - elapsed`, updates `lastDispatchAt`).
- **Release:** `finally` block ensures failover after failure still frees the slot.
- **Defaults:** `0` = no-op (global semaphore cap only, no throttle).

### FR-6 (Streaming Web Translation)
- **Port:** `WEB_STREAM_PORT = 'TRANSLATE_WEB_STREAM'`.
- **Background:** `initWebStreamPortListener` mirrors PDF path — reuses `service.translateStream` + SSE parser, emits `piece`/`done`/`error`, writes fresh translations to cache (partial-back-fill guard).
- **Content:** `streamTranslate` helper opens port, applies incremental `applyTranslation`/`applyInlineTranslation` per delta (in-place spinner swap), resolves to `TranslationResultMessage`. Non-streaming fallback on error.
- **UI:** `enableStreamingTranslation` toggle (default `false`, opt-in).

### FR-7 (Cross-Session Web Resume)
- **Pure lib `lib/webResume.ts`:** `WebResumeSnapshot { url, contentHash, targetLanguage, capturedAt, pieces: ResumePiece[] }`; `computeResumeKey` (`webResume:` prefix); serialize/deserialize; `isSnapshotFresh` (7-day TTL); `saveSnapshot`/`loadSnapshot`/`evictResume` (LRU 50-URL cap); `deriveContentHash` (SHA-256 with fallback).
- **Content wiring:** `startTranslation` calls `restoreFromSnapshot` (text match, targetLanguage gate) and registers `pagehide`/`beforeunload` writer. `stopTranslation` writes final snapshot + resets registration flag.
- **Match by text:** Piece IDs are regenerated per extraction; snapshot stores text+translation.

## Learnings Extracted (from `learnings.md`)

### Patterns Discovered
- **3-place settings change:** Any new `ExtensionSettings` field must be added to (1) interface, (2) `DEFAULT_SETTINGS`, (3) `extractSettings()` — else `useSettings()` silently drops it.
- **Pure helper extraction makes handler logic testable:** `splitPiecesIntoBatches`/`dedupPiecesByText` are pure (unit-tested directly); handler tests cover integration (fetch count, dupe re-hydration).
- **Viral exports require mock updates:** Adding `getCachedFailure`/`cacheFailure` to cacheManager broke 5 background test files that mocked a subset of exports. Must add new exports to ALL mock factories.
- **idb-keyval silently fails in node/jsdom:** `catch` blocks swallow errors; integration tests relying on real read/write return null/miss. Unit-test pure helpers; test wiring via `vi.spyOn`.
- **Match resume by text, not piece id:** Piece IDs (`lp-<counter>`) are regenerated per extraction; snapshot stores text+translation.

### Gotchas Encountered
- **`inlineEl.title` must be raw `translatedText`:** `getInlineTranslationText()` (clone logic) prefers `title` and relies on it being the clean unwrapped text. Setting title to `formatInlineText(...)` broke the inline-clone test.
- **Python migration heuristic matched `providerConfig`:** The `maxRpm: N,` pattern inside `providerConfig` objects (not just `PoolKey`) triggered wrong additions. Must verify no `ProviderConfig` gained slot-level fields.
- **Single-key + 500 error opens breaker:** The "failover-safe" release test used a clientError (400) to isolate slot-release from breaker behavior.
- **Flaky tests exist:** 1-3 intermittent failures under parallel load (subtitle coordinator timeout) that pass on immediate re-run. Confirmed by 3 consecutive clean full runs.

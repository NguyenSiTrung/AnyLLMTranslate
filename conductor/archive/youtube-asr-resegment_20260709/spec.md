# Spec: YouTube ASR Subtitle Sentence Re-alignment

**Track type:** Feature  
**Related reference:** Immersive Translate `generalRule.ytAsrConfig` + local `Vq` pipeline  
**Date:** 2026-07-09

## Overview

YouTube auto-generated (ASR) captions are often fragmented mid-sentence, which degrades LLM translation quality. This track adds a **pre-translate re-alignment** step: re-chunk ASR word/cue segments into coherent sentence-level cues **before** they enter the existing subtitle translation pipeline.

v1 ships a **local, config-driven rule engine** (Immersive free-path parity). Architecture and settings leave clear hooks for a **future AI/server re-align path** (not implemented beyond stub/settings design in this track).

## Functional Requirements

### FR-1 — Runtime gate (YouTube ASR only)
- Re-alignment runs only for YouTube **auto-generated / ASR** tracks (`kind=asr`, `isAutoGenerated`, or equivalent URL/track signal).
- Human / non-ASR YouTube captions are **not** re-aligned in v1.
- Other platforms do not opt in in v1.

### FR-2 — Pure resegment module
- Core logic lives in a pure library (e.g. `lib/youtubeAsrResegment.ts` or `lib/asrResegment.ts`), not buried only inside the handler.
- Input: timed words and/or `SubtitleCue[]` + language code + config.
- Output: `SubtitleCue[]` with rebuilt `startTime` / `endTime` / `text`.
- Deterministic and unit-testable (no Chrome APIs).

### FR-3 — Word-level preferred, cue-level fallback
- When JSON3 events expose `segs` with timestamps (and/or word offsets), flatten to word stream and run full split/merge (Immersive-style).
- When only coarse cues exist (srv3 / already-flattened), apply a reduced cue-level resegment (gap + max length / hanging-fragment merge).
- Do not require a forced re-fetch of JSON3 in v1 if the intercepted body is already usable.

### FR-4 — Language config
- Config shape inspired by Immersive `ytAsrConfig.langsConfig`:
  - **`base`**: generic `splitConfig` / `mergeConfig` (min interval, max words).
  - **`en`**: English break words, skip words, endWords, startWords, endCompatibleConfigs.
- Resolve language with fallback: exact code → primary subtag → `base`.
- Config is versionable/defaulted via extension settings defaults (not hard-coded only in one call site).

### FR-5 — Pipeline integration
- Re-align **after** parse / track identification as ASR, **before** translation batching / cache keys that depend on final source text.
- Coordinator or YouTube path calls the pure helper when the feature flag is on and the track is ASR.
- Existing reading-speed timing (`subtitleTiming`) continues to apply **after** re-align (or remain on display path as today — order must be documented and tested so durations stay consistent).
- Cache keys must reflect re-aligned source text (same as any other source change).

### FR-6 — Settings UX
- Options → Subtitles → **YouTube** area: one toggle, e.g. **“Improve auto-generated captions”**.
- Default: **on**.
- Disabled/dimmed when master subtitle translation is off (consistent with existing Subtitles section patterns).
- Persist under settings (e.g. `subtitleSettings.youtubeAsrResegment` or nested `youtubeAsr: { enable: boolean, aiEnable?: boolean }`).
- **AI path:** field/hook reserved (`aiEnable` default false; UI may omit control or show disabled “Coming soon” — no cloud/server call in v1).

### FR-7 — Future AI hook (design only)
- Document interface for optional AI resegment (e.g. `requestAiAsrResegment(events, lang) → SubtitleCue[]`).
- No dependency on Immersive’s `subtitles/yt-asr-subs` API.
- If implemented later: BYOK via existing provider pool; mutually exclusive or preference over local when enabled (parity note in plan).

### FR-8 — Observability
- Debug logging (existing debug facilities) when re-align runs: track lang, input cue/word count, output cue count.
- Fail-open: on resegment error, fall back to original parsed cues and continue translation.

## Non-Functional Requirements

- **Correctness over cleverness:** Prefer stable English rules + simple base; avoid ML in v1.
- **Performance:** Re-align full track once (or once per track load), O(n) over words/cues; no per-frame work.
- **Tests:** High coverage on pure lib (fixtures from synthetic ASR fragments + golden cases for en).
- **TDD:** Pure algorithm and settings defaults covered before wiring.
- **No host pollution:** No extra DOM for this feature beyond existing subtitle overlay.

## Acceptance Criteria

1. With toggle **on**, YouTube **ASR** English (and base-lang) captions are re-chunked into fewer, more sentence-like cues before translate requests.
2. With toggle **off**, behavior matches current parse → translate path.
3. Non-ASR YouTube tracks are unchanged regardless of toggle.
4. Unit tests cover: flatten segs, split on break words/gaps, merge hanging end/start words, endCompatible merge, cue-level fallback, language fallback to `base`, fail-open path.
5. Settings toggle persists and is reflected at runtime without full extension reload (or documented reload requirement if storage load already works that way for subtitle settings).
6. Types/settings include an explicit AI-enable (or equivalent) hook defaulting off; no production AI resegment call.
7. `pnpm test` and `pnpm lint` pass for touched areas.

## Out of Scope

- Server-side / Immersive cloud ASR merge API.
- Implementing AI resegment with the user’s LLM (hook/design only).
- Re-aligning human captions or non-YouTube platforms.
- Forced JSON3 upgrade fetch when only srv3 is intercepted.
- Full multi-language word lists beyond `en` + `base`.
- Changing bilingual dual-display merge algorithms for human+translation tracks.
- Live chat / live ASR streaming special cases (unless already covered by existing live path — do not expand scope).

# YouTube Caption Request Guards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent stale YouTube player metadata from creating invalid proactive
caption requests, and bound automatic retries to one attempt per navigation.

**Architecture:** Keep all guards in `content/subtitleCoordinator.ts`, the
only component that owns discovered tracks and starts proactive timed-text
fetches. Reject stale metadata on entry and repeat the ID comparison immediately
before the YouTube pipeline; carry the navigation-and-ID check through direct
fetch, background fallback, and native-caption fallback so asynchronous state
cannot bypass the guard.
Automatic attempts record only an in-memory navigation-scoped key; manual
selection remains an intentional retry path.

**Tech Stack:** TypeScript, Chrome MV3 content scripts, Vitest + jsdom.

## Global Constraints

- A proactive request requires equal active-page, track, and timed-text URL video IDs.
- Rejection must occur before direct fetch, `FETCH_SUBTITLE`, and native CC fallback.
- A prior navigation's in-flight request must not coalesce with the current navigation.
- Do not change playback CDN or passive interception behavior.
- No commit or push without explicit user authorization.
